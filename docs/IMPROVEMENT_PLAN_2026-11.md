## 2. 반복 문제 심층 분석

### R1. KB 해시가 매일 바뀐다 (가장 큰 비용원)

근거 — `events_latest.json` 15회(10-20~11-09)의 `source_content_hash`

| 증권사 | 이벤트 수 | 해시 변경/관측 | 신선 추출 일수 |
|---|---|---|---|
| KB | 7 | **14/15** (전건, 15일에 15개 값) | 관측일의 93~100% |
| 삼성 | 9 | 0~3 | 0~6 (플래그 건, R3) |
| 미래·한투·NH | 18 | 0~1 | 0~1 |

원인 분석
1. **해시 입력이 LLM 입력과 다르다.** KB 4건은 `extract_method='ocr'` 이고 로그에 `본문구조화` 호출이 없다 = 본문 텍스트가 `TEXT_MIN`(200자) 미만이라 LLM 에는 이미지 만 간다. 그런데 `source_content_hash` 는 그 짧은 텍스트(`_hash_text`)를 항상 포함한다. LLM 이 보지도 않는 200자 미만의 페이지 잔여 텍스트가 캐시를 깬다.
2. **공통 라인 제거는 "페이지마다 다른 휘발 값"을 못 지운다.** `hash_text_per_firm` 은 같은 실행에서 2건 이상에 똑같이 나오는 줄만 지운다. 조회수·게시일·세션성 값처럼 페이지마다 값이 다른 줄은 남는다(9월 문서 S2 의 "조회수/등록일/D-day 패턴 제거"는 구현되지 않았다).
3. **이미지 URL 집합의 안정성 미검증.** 대표 이미지(`image_url`)는 15일간 안정(변경 0~1회)이지만 해시는 전체 URL 목록을 쓴다. 지연 로드로 수집 장수가 달라지면 해시가 바뀐다 — 스냅샷이 없어 확인 불가.

→ 어느 성분인지 확정하려면 **계측이 먼저**다(§3 A1). 다만 A2(입력 충실 해시)·A3(재추출 간격)는 원인과 무관하게 효과가 난다.

### R2. 추출 변이 간 왕복 — 게이트를 통과하는 덮어쓰기

근거 — `event_changes` 10-13 이후 변경 94건 중 KB 69건(조건 51, 혜택 18). 기간 변경은 0건.

- id 37 「ETF 매매수수료」 conditions: 변이 A(3줄) ↔ B(4줄, "신청: 별도 이벤트 신청 없이 적용" 추가)가 10-26·27·11-02·04·05·06 에 **정확히 교대**. 수치 토큰은 양쪽 동일(`1`, `1개`)인데 파서 유래 `apply_required` 가 `None ↔ False` 로 바뀌어 시그니처가 달라진다(코드로 재현 확인).
- id 71 「연금저축 순입금 시즌4」 conditions: 변이 3종(A·B·C)이 순환. 서로 수치 토큰이 조금씩 달라(`600만원`, `27.1.1~1.31` 등) 부분집합 관계가 아니므로 "유실" 판정도 안 걸린다.

원인: 게이트가 **직전 승인값 하나**와만 비교한다. 같은 원문에서 LLM 이 2~3개 변이를 번갈아 내면 매번 "실질 변경"이다. R1 이 매일 재추출을 일으키는 한 이 왕복은 끝나지 않는다.

### R3. 검토 플래그가 캐시를 막고, 무근거 건은 영원히 재시도한다

`normalize.py` 의 `cache_ok` 는 `not old.needs_review` 를 요구한다. 그런데 플래그의 다수는 **재추출해도 똑같이 다시 붙는 결정론적 플래그**다.

| 플래그 | 일수(10-14~11-09) | 재추출로 해소되는가 |
|---|---|---|
| 제외재원 조항 추출 누락 (G8) | KB TDF 15일, 삼성 3건 10·5·4일 | 아니오 — 오탐 |
| 목록 요약 폴백(상세 추출 실패) | 한투 2건 13·8일 | 예 (R5 가 원인) |

- **G8 오탐**: 이전 유치형 판정 정규식 `이전|가져오|수관|전환` 이 "이벤트 **이전** 보유 중인", "디폴트옵션 **전환**" 에도 맞는다(재현 확인). 원문에 "제외" 한 단어만 있어도 누락으로 본다.

## 3. 개선 방안

설계 원칙 4가지
1. **캐시 키는 LLM 에 실제로 넣는 입력으로만 만든다.**
2. **재추출은 필요할 때만, 값 교체는 재현될 때만.**
3. **검토 플래그는 사람용 신호다 — 재추출 사유가 아니다.**
4. **실패와 원인은 흔적을 남긴다.**

## 5. 한계 — 이 검토가 확인하지 못한 것

- **KB 해시의 휘발 성분**: 원문이 저장되지 않고, 이 세션에서는 증권사 사이트 접속이 차단돼(4개 사이트 모두 연결 불가) 직접 확인하지 못했다. R1 의 원인 1은 로그로 확인된 사실이고, 원인 2·3은 코드 근거의 추정이다. A1 계측 후 확정한다.
- **미래에셋의 스토어 이동 조건**: 11-06·11-09 로그로 현상은 확인했으나 유발 조건(UA·팝업·점검 여부)은 미확인. B1 은 두 모드에 공통으로 듣는 방어이며 `collect-test` 로 검증이 필요하다. 10-15·22·26, 11-05 의 실패 모드는 로그를 열지 않았다.
- **cron 이동의 효과**: GitHub 예약 실행 지연은 보장이 없다. C1 은 관찰 후 판단한다.
- **A6 확인 추출의 재현율**: Gemini 가 같은 입력에 같은 시그니처를 낼 확률은 측정된 적이 없다. P1 첫 주에 `confirm` 호출의 일치율을 C3 집계로 본다.
